    Preparation of forest inventories

    SIMANFOR processes forest inventories structured in Excel spreadsheet format (.xlsx). To facilitate the user workflow and ensure consistency with the simulation engine, the platform provides a unified file per model that acts simultaneously as a standardized template and as an initial inventory with real example data ready to simulate or replace.

    Workbook structure by modeling level

    The number and naming of sheets in the inventory workbook depend on the design of the selected forest model:

    • Stand-level models:
    • Contain a single worksheet named Plots in English inventories or Parcelas in Spanish inventories.
    • Each row represents a sample unit or plot, described using aggregated stand metrics (age, density, basal area, quadratic mean diameter, dominant height, etc.).
    • Individual-tree models:
    • Require two interconnected worksheets:
      1. Plot worksheet: Named Plots (EN) or Parcelas (ES), with one row per plot containing site, environmental, and stand-level variables.
      2. Tree worksheet: Named Trees (EN) or Pies_mayores (ES), with one row per measured tree.
    • Relational linkage: Both sheets must share the plot identifier field (ID_plot in English or ID_parcela in Spanish) to link trees to their corresponding plot.

    Header color convention

    SIMANFOR templates incorporate a visual color code in the first row of each worksheet to identify mandatory versus complementary data:

    • Sage green header (#D9EAD3, bold dark green text):
    • Mandatory variable.
    • Essential input without which the simulation engine cannot initialize the model or project stand dynamics.
    • Stand-level examples: ID_plot, age, density, basal_area, dg, dominant_height.
    • Tree-level examples: ID_plot, ID_tree, species, dbh, expan.
    • Neutral gray header (#F2F2F2, dark gray text):
    • Optional or complementary variable.
    • Auxiliary field that can be estimated or automatically imputed by the SIMANFOR engine if omitted.
    • Tree-level examples: total_height (when the model provides parameterized height-diameter curves), dominant_height, seccion_id, subseccion_id.
    • Geographic examples: Province (required only for models based in Spain that reference SNFI volume tariffs, optional for international or aggregate models).

    Additionally, each header cell includes a native Excel note visible on hover, indicating the canonical variable name, official measurement units, and mandatory/optional status.

    Column naming guidelines

    To ensure seamless data ingestion, column headers in Excel workbooks must match the official localized names in the SIMANFOR variables database or their established abbreviations:

    • Diameter at breast height (1.30 m): Use dbh in English inventories or dap in Spanish (or abbreviation d).
    • Total tree height: Use total_height in English or altura_total in Spanish (or h).
    • Tree expansion factor: Use expan or expansion_factor in English, and expan or factor_expansion in Spanish.
    • Quadratic mean diameter: Use dg.
    • Basal area: Use basal_area in English or area_basimetrica in Spanish (or g).
    • Stand density: Use density in English or densidad in Spanish (or n).
    • Stand age: Use age in English or edad in Spanish.

    Species encoding

    In tree-level inventories, the species column (or especie in Spanish) accepts two identification systems:

    • Numeric SNFI code: Official integer code from the Spanish National Forest Inventory (e.g. 21 for Pinus sylvestris, 41 for Quercus robur).
    • Scientific Latin name: Strict binomial designation (e.g. Pinus sylvestris, Quercus pyrenaica).
    • Bidirectional resolution: The SIMANFOR engine automatically translates numeric codes into scientific names or vice versa according to the model requirements.
    • Restriction: Common or vernacular names (e.g. "Scots pine", "oak", "beech") are not permitted due to taxonomic ambiguity.
    • To view the complete species reference, consult the SNFI species codes catalogue or download the file SNFI4_species_codes.csv.

    Provincial coding and SNFI tariffs

    For plots located in Spain, the Province field in the Plots worksheet determines the selection of official SNFI regional volume tariffs with and without bark as well as biomass equations:

    • Recommended format: Two-digit numeric code from the Spanish National Statistics Institute (INE) (e.g. 32 for Ourense, 40 for Segovia, 49 for Zamora). This is the most reliable format to prevent character encoding issues or spelling variations.
    • Alternative format: Official administrative province name (e.g. Valladolid, Jaén, Burgos).
    • International or aggregate models: For models applied outside Spain (Romania, Mexico, Norway, USA) or stand-level models not referencing SNFI equations, this field is not needed.
    • To view the complete list of provincial codes, consult the INE provincial codes guide or download the file ine_regions_provinces.csv.
